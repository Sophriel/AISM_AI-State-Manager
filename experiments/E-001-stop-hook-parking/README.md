# E-001. Stop 훅 파킹 실험

AISM의 핵심 가정을 확인한다:
**살아 있는 Claude Code 세션을 Stop 훅 안에서 대기(파킹)시켜 두었다가, 외부에서 다음 지시를 넣어 같은 맥락으로 이어서 일하게 할 수 있다.** (FEATURES S-5, S-7, S-8)

## 1차 결과 — Linux 헤드리스 (2026-11-11, Claude Code 2.1.322)

| 확인 항목 | 결과 |
|---|---|
| Stop 훅이 90초 대기해도 취소되지 않음 (`timeout: 900`) | ✅ |
| `{"decision":"block","reason":"..."}` 반환 시 Claude가 멈추지 않고 reason을 지시로 수행 | ✅ |
| 같은 세션 맥락 유지 (첫 프롬프트의 비밀 단어를 기억) | ✅ |
| 이어진 작업이 끝나면 Stop 훅이 다시 발화 (`stop_hook_active: true`) | ✅ |
| 훅 입력에 `session_id`, `last_assistant_message`, `stop_hook_active` 포함 | ✅ |

미확인 → Windows 대화형에서 확인 필요 (아래).

## 2차 — Windows 대화형 테스트 (직접 실행)

준비물: Node.js, Claude Code (이미 설치됨).

1. `run.bat` 실행 → 새 Claude Code 세션이 뜨고 "알겠어"라고 답한다.
2. 답이 끝나면 세션이 **파킹**된다 (작업 중 표시가 계속될 것).
3. 다른 cmd 창에서:
   ```
   release.bat 비밀 단어가 뭐였는지 말하고, result.txt 파일에 DONE 이라고 써
   ```
4. 세션 창에서 Claude가 이어서 작업하는지 본다. 끝나면 다시 파킹된다.
5. 종료: `release.bat STOP`

### 기록할 것

| # | 확인 항목 | 결과 |
|---|---|---|
| W1 | 파킹 중 창이 어떻게 보이나 (스피너? 멈춤?) | 1회차: 작업 중 스피너 유지, 끝나고 `Churned for 30m 5s` 표시 |
| W2 | 파킹 중 사용자가 타이핑할 수 있나 / ESC로 끊을 수 있나 / 끊으면 어떻게 되나 | ✅ 입력+엔터 → 프롬프트 **예약**. ESC → 훅 중단 후 예약 프롬프트 즉시 실행. ESC 이후 응답이 끝나면 Stop 훅 다시 발화 ✅ |
| W3 | release 후 같은 맥락으로 이어서 작업하나 (바나나 기억) | ✅ 55초 파킹 → 지시 전달 → '바나나' 기억, result.txt 작성 → 재파킹 → STOP으로 정상 종료 |
| W4 | 10분 이상 파킹 후 release 해도 정상인가 (`timeout: 1800`) | 1회차: release 없이 30분 파킹 → 타임아웃 도달 시 훅 취소, 세션은 정상 종료(멈춤 허용과 동일). release 후 동작은 미확인 |
| W5 | 로컬 Qwen(`ANTHROPIC_BASE_URL`)에서도 동일하게 동작하나 | ✅ |
| W6 | `hook.log`에 이상한 점은 없나 | |

W2가 가장 중요하다. 끼어들 수 없다면 "결정 필요" 상황에서는 파킹하지 말고 멈춤을 허용해야 하고(현재 설계대로), 끼어들 수 있다면 더 유연하게 설계할 수 있다.

### 1회차 (2026-11-11 16:36~17:06, Windows 대화형)

release 없이 방치. 16:36:50 파킹 시작 → `timeout: 1800`(30분) 도달 → 훅 취소 → 세션이 멈춤 허용 상태로 종료. hook.log에는 파킹 시작까지만 기록(취소된 훅은 로그를 남기지 못함).
→ **타임아웃은 안전하게 실패한다** (세션이 깨지지 않고 평소처럼 입력 대기). 서버는 타임아웃 전에 스스로 풀어줘야 하고, 놓치면 S-9(`--resume`)로 복구한다.

### 2회차 (2026-11-11 17:16~17:27, Windows 대화형, 클라우드 모델)

- W2: 파킹 중 입력은 예약되고, ESC로 훅을 끊으면 예약 입력이 바로 실행됨 → **사람이 언제든 끼어들 수 있다.**
- W3: release 지시가 같은 세션 맥락으로 실행되고, 끝나면 다시 파킹됨. `STOP`으로 정상 종료.
- 추가 확인: ESC로 끊은 뒤 그 응답이 끝나면 Stop 훅이 다시 걸림. W5 로컬 Qwen에서도 동일하게 동작.

**결론: E-001 완료. 핵심 가정(파킹 + 지시 전달 + 사람 끼어들기)이 Windows 대화형, 클라우드·로컬 모델 모두에서 성립한다.**

## 파일

- `stop_hook.js` — `release.txt`가 생길 때까지 대기. 내용이 `STOP`이면 멈춤 허용, 아니면 그 내용을 `block` reason으로 전달. 로그는 `hook.log`.
- `run.bat` — 훅 절대경로를 넣은 settings 파일을 생성하고 세션 시작.
- `release.bat` — `release.txt` 작성 (= 서버가 할 일을 손으로 흉내).
