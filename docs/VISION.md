# Vision

## 문제

- 3세션 워크플로우(PLAN ⇄ VERIFY 반복 → TODO → CODE)를 운용 중인데, 세션마다 역할을 매번 지시해야 한다.
- 세션이 끝날 때마다 다음 세션을 수동으로 띄우고 맥락을 넘겨야 한다.
- 기존 오케스트레이션 도구는 (a) Claude Code를 하네스로 쓰지 않거나, (b) 흐름이 일직선이라 REVISE → PLAN 같은 되돌림 루프를 표현하지 못하거나, (c) 역할별로 다른 엔드포인트(클라우드 / 로컬 LLM)를 줄 수 없다.

## 지금의 수동 흐름 (자동화 대상)

1. 플랜 세션(클라우드 모델)에 작업을 설명하고 플랜 작성을 지시한다.
2. 플랜이 나오면, 사용자가 결정할 부분이 있으면 플랜 세션과 논의한다.
3. 논의할 게 없으면 로컬 LLM Claude Code 세션에 "플랜 검토해"라고 지시한다.
4. 문제가 있으면 검증 세션이 plan-verify 파일로 저장한다.
5. 사용자가 플랜 세션으로 가서 "plan-verify 확인해"라고 지시한다. → 2로 반복.

두 세션은 **계속 켜져 있고**, 사용자는 그 사이를 오가며 **전달자** 역할과 **결정자** 역할을 한다.
AISM은 전달자 역할을 대신하고, 결정이 필요할 때만 멈춰서 사용자를 부른다.

## 목표

1. **역할 고정** — 세션이 시작될 때부터 자기 역할을 안다. 컨텍스트 압축 후에도 유지된다.
2. **자동 핸드오프** — 세션 종료를 확정적으로 감지하고, 산출물 파일을 읽어 다음 역할을 띄운다.
3. **조건 분기와 루프** — 검증 결과에 따라 앞 단계로 되돌린다. 무한 반복은 상한으로 막는다.
4. **사람 게이트** — 지정한 지점에서는 사람 승인 없이 넘어가지 않는다.
5. **가시성** — 작업별 현재 상태, 판정, 이력을 GUI로 한눈에 본다.

## 원칙

- **하네스는 Claude Code를 그대로 쓴다.** 도구 실행·권한·컨텍스트 관리를 재구현하지 않는다.
- **판단 근거는 파일이다.** 터미널 출력을 파싱하지 않는다. 상태는 산출물 파일과 훅 이벤트로만 판단한다.
- **상태 머신은 결정적이다.** 다음 단계를 LLM이 고르지 않는다.
- **Windows 우선.** 주 개발 환경이 Windows다.
- **로컬 자원 제약을 존중한다.** 로컬 엔드포인트는 동시 실행 1.

## 비목표 (당분간)

- 범용 멀티 에이전트 플랫폼 (팀 모드, 다수 프로바이더 추상화)
- 앱 내부에 대화형 터미널 내장
- 병렬 실행 최적화
- 클라우드 호스팅 / 다중 사용자
