# 0025. 역할별 엔드포인트(모델) 선택 — 작업 단위, 창이 열려 있으면 막음

- 상태: 확정
- 날짜: 2026-11-23
- 출처: 261123-role-endpoint-select plan-v3 (§3, §6 D1~D5)

## 맥락

역할이 쓰는 엔드포인트(모델)는 설정 파일(`roles.<role>.endpoint`)로 고정되어 cloud↔local 전환은 `aism.config.json` 수정이 필요했다. 병렬 작업(ADR 0022)에서는 작업마다 다른 모델이 필요할 수 있는데 설정은 전역이라 작업끼리 영향이 갔다. 사용자 요청(D1~D5): 작업 화면에서 역할별 모델을 고르고, 그 작업에만 적용하며, 그 역할 세션 창이 열려 있으면 막는다.

## 결정

- **작업 단위** (D1): 선택은 작업 상태(`Task.endpoints`, 선택적 키)에만 저장 — 설정 파일은 바꾸지 않는다. 새 작업은 설정 기본값(`roles.<role>.endpoint`)으로 시작한다.
- **선택지** (D2): 설정 `endpoints`의 이름(지금 `cloud`/`local`). 클라우드 모델 세부 선택(`--model`)은 없다.
- **잠금** (D3): 그 역할 세션 창이 살아 있으면(배정 없음·detached가 아닌 working·parked·idle·unbound) 선택을 막는다 — 서버 409, UI 비활성. 화면 값과 실제 세션 모델이 어긋나지 않게.
- **다시·이어서 띄우기** (D4): 모델을 바꾼 뒤 다시 띄우기와 이어서 띄우기(`--resume`) 둘 다 허용 — `--resume`은 대화 기록만 이어 받고 엔드포인트는 env.bat이 정한다.
- **대기 중 launch 항목** (D5): 로컬 대기열에 launch 항목이 있는 역할(창 없음)도 선택 변경을 허용한다 — 옛 대기열에서 항목을 빼고 새 엔드포인트 기준으로 재전달(cloud면 즉시 실행, 로컬이 비어 있으면 즉시 실행, 사용 중이면 새 대기열 끝에).

## 상태 호환

`Task.endpoints`는 **선택적 키** — `isCurrentState`는 작업 키 8개(기존) 또는 9개(+`endpoints`)를 허용한다. 업그레이드 시 진행 중 작업이 버려지지 않는다. 상태의 엔드포인트 이름이 설정에 없으면(설정에서 지움) 역할 기본값으로 동작한다(`effectiveEndpoint`).

## 결과

- 서버: `POST /api/tasks/endpoint`, `Orchestrator.setEndpoint`, `effectiveEndpoint(task, role)` — 모든 launch 경로(자동 launch·relaunch·newTask)와 로컬 대기열·코딩 잠금 대상 판정이 이것을 기준으로 한다. `getState`에 `endpointNames`·`endpoints` 추가.
- 웹: 역할 행 맨 앞의 모델 선택 드롭다운(창이 열려 있으면 비활성), 타임라인 launch 줄에 실제로 띄운 엔드포인트 표시(`Launch  CODER (local)`). 모델 변경 자체는 타임라인에 기록하지 않는다(plan-v5, N1).
- 엣지: 긴 클라우드 대화를 로컬로 이어서 띄우면 로컬 컨텍스트를 넘을 수 있어 다시 띄우기 권장(README).

## 검토한 대안

- **설정 파일에 저장**: 사용자 결정 D1(작업 단위) — 병렬 작업끼리 영향 없음.
- **`--model`까지 고르기**: D2로 제외.
- **`isCurrentState`에 필수 키 추가**: 진행 중 작업 state가 통째로 버려짐 — 선택적 키로.
- **세션이 살아 있어도 바꾸고 다음 띄우기부터 적용**: D3(막음)으로 기각 — 화면 값과 실제 세션 모델이 어긋나지 않게.
