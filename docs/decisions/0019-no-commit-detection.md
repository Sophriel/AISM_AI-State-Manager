# 0019. 커밋 완료는 판정하지 않는다 — 자동은 커밋 계획까지, 커밋은 사용자 허가로만

- 상태: 확정
- 날짜: 2026-11-18
- 출처: m3-polish plan-v1 (§3 A·B)
- 대체: ADR 0017의 커밋 완료 판정·committed 알림·pendingAction committed

## 맥락

ADR 0017은 `todo-vT-commit.md`에 `## 커밋 로그` 줄이 있으면 커밋 완료로 판정하고 `committed-v<T>` 알림·pendingAction `committed`을 냈다. 2026-11-17 테스트(m3-commit-projects todo-v1-notes N3)에서 이 판정이 계획 단계에서 오판되는 문제가 확인됐다 — 자동 진행은 커밋 계획 작성까지로 한정하고, 커밋 실행은 사용자 허가로만 하기로 했다(D1).

## 결정

- `TodoSnapshot.committed`(`## 커밋 로그` 줄 존재)를 삭제한다. 서버는 커밋 완료 여부를 읽지 않는다.
- c9의 committed 분기·`committed-v<T>` 알림을 삭제한다. 알림은 `commit-plan-v<T>`("커밋 계획 작성 완료 — CODER 창에서 확인하고 허가하세요")만 낸다.
- pendingAction `done.commit`은 `"none" | "planned"`(계획 파일이 있으면 planned). 체크리스트가 없고 계획이 있으면 `commit` 종류.
- 커밋 계획이 있으면(커밋 대기) CODER 배지는 "사용자 차례"로 유지한다(D2). 커밋 완료를 판정하지 않으므로 배지·안내는 **작업 종료까지 그대로** 남고, 사용자는 커밋 후 작업 종료로 정리한다.
- `## 커밋 로그` 절은 CODER 규약(`roles/coder.md`, `roles/_workflow.md` 형식)에 사용자 확인용으로 그대로 남긴다.

## 결과

- 커밋을 완료한 뒤에도 배지·안내가 작업 종료까지 남는다 — 사용자는 커밋 후 **작업 종료**로 정리한다.
- `commit-plan-v<T>` 알림은 한 번만(중복 방지) 나가고, 계획을 고친 뒤에도 다시 나오지 않는다 — 작업 카드 정보형 문구로 확인한다.

## 검토한 대안

- **커밋 로그 해시를 git으로 검증**: 자동 진행이 계획까지이고 커밋은 사용자 허가로만 하므로 별도 처리가 필요 없음(D1).
- **git 기록(로그)으로 완료 판정**: 위와 같은 이유.
- **PostToolUse 훅으로 커밋 감지**: 위와 같은 이유.
- **CODER 발화로 완료 보고**: ADR 0002(상태 판정은 파일과 훅으로만, LLM 판단 금지)에 위배.
