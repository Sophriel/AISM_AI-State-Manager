# 0017. CODER는 DONE 후 커밋 계획을 쓰고, 사용자가 CODER 창에서 허가하면 커밋한다

- 상태: 확정
- 날짜: 2026-11-17
- 출처: m3-commit-projects plan-v2 (§3 A~C)

## 맥락

CODER가 구현을 마치고 Status를 DONE으로 설정한 뒤, 변경 사항을 어떻게 커밋할지는 사용자가 직접 확인·커밋해야 했다 — 오케스트레이터는 구현이 끝났는지, 커밋이 필요한지 알 수 없었다. 사용자 요청(D1~D3): CODER가 끝나면 PLANNER의 체크리스트 작업과 **병렬**로 커밋 분할 계획을 쓰고, 사용자가 **CODER 창에서** 허가하기 전까지는 커밋하지 않으며, push는 하지 않는다.

## 결정

- **파일**: 작업 폴더의 `todo-vT-commit.md`(T = 최신 todo), 소유자 CODER. 형식: `# todo-vT 커밋 계획` / `## 커밋 N`(`- 메시지:` `- 파일:`) / `## 제외`(작업과 무관한 변경). 허가 후 커밋하면 파일 끝에 `## 커밋 로그` 절을 추가하고 커밋마다 한 줄 `- <짧은 해시> <메시지 첫 줄>`.
- **c9 병렬 지시**(CODER, DONE) — 위에서 처음 맞는 것:

  | 조건 | CODER | 그 외 |
  |---|---|---|
  | T null / 대상 프로젝트가 git 레포가 아님 | allow | `done-v<N>` 알림 + 체크리스트 지시(기존과 같음) |
  | 커밋 계획 없음, `commitplan-v<T>` 미기록 | **block(instructionCommitPlan(T))** 후 기록 | `done-v<N>` 알림 + 체크리스트 지시 — 같은 평가에서 함께 나가므로 두 세션이 동시에 일한다 |
  | 커밋 계획 있음, 커밋 로그 없음 | allow | info `commit-plan-v<T>` "커밋 계획 작성 완료 — CODER 창에서 확인하고 허가하세요" + 체크리스트 지시(아직 안 갔으면) |
  | 커밋 로그 있음 | allow | info `committed-v<T>` "커밋 완료 — push는 직접 하세요" |

  git 여부는 `MachineInput.projectIsGit`으로 평가 입력에 넣는다(Orchestrator가 프로젝트 정보로 채움).
- **허가는 CODER 창에서**(D2): `roles/coder.md`의 Rules 첫 줄을 "이 세션에서 사용자가 커밋 계획을 허가한 경우에만 커밋·스테이지, push는 절대 하지 않는다"로 바꾸고, DONE 후 지시를 받으면 계획을 쓰고 멈추며, 허가를 받으면 계획대로만 커밋한다.
- **push 안 함**(D3): push는 사용자가 직접 한다.
- **git 아닌 프로젝트는 건너뜀**: 대상 프로젝트가 git 레포가 아니면 커밋 계획 지시를 하지 않는다.
- **알림·표시**: `commit-plan-v<T>`는 토스트 대상(사용자 할 일), `committed-v<T>`는 토스트 없음. pendingAction `done`에 `commit: "none" | "planned" | "committed"`을 붙이고, 계획은 있는데 아직 커밋하지 않았고 체크리스트가 없으면 새 종류 `commit`. `targetOf`: `done`+`planned` → coder(허가 대기 배지), `commit` → coder.

## 결과

- CODER가 커밋 계획을 쓰지 않고 멈추면: `commitplan-v<T>` 기록이 있으므로 다시 지시하지 않고 allow(사용자가 CODER 창에서 직접 요청).
- 사용자가 허가 대신 계획 수정을 요청하면: CODER가 계획을 고치고 멈춤 → 계획 있음·로그 없음 → `commit-plan-v<T>` 알림은 이미 나갔으므로 다시 안 나가고, 작업 카드는 계속 허가 안내.
- 대상 레포에 작업 전부터 있던 변경: 계획의 `## 제외`로 분리해 커밋하지 않는다.
- `todo-vT-commit.md`는 플랜 폴더(대상 레포에서 gitignore되는 게 보통)에 있어 커밋 대상이 아니다.
- 미결: `--disallowedTools`가 CODER에는 없으므로 허가 없이 커밋할 위험은 역할 규약에만 의존 — 체크리스트에서 허가 전 커밋이 없는지 확인.

## 검토한 대안

- **CODER가 DONE 직전 같은 턴에 커밋 계획까지 쓰게(역할 규약만)**: PLANNER 체크리스트 지시와 순차가 됨 → 서버가 DONE Stop에서 두 세션에 동시에 지시(D1 병렬).
- **UI 승인 버튼으로 커밋**: 사용자가 CODER 창에서 직접 허가하기로 결정(D2).
- **커밋 로그를 별도 파일로**: 계획과 결과가 한 파일에 있으면 확인이 쉬움 → 같은 파일 `## 커밋 로그`.
