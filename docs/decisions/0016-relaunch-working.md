# 0016. 작업 중으로 보이는 세션도 확인 후 다시 띄우기·이어서 띄우기

- 상태: 확정
- 날짜: 2026-11-16
- 출처: m2-polish plan-v3 (§3 D)

## 맥락

ADR 0011의 알려진 한계: 세션이 `working`으로 보이는 동안 사용자가 창을 닫으면 서버는 그 사실을 알 수 없다(창 닫힘 미감지). 이 상태에서 relaunch가 거부되면(`session is working`)사용자는 새 세션을 띄울 수 없어 작업이 멈춘다(N4).

## 결정

- **relaunch**: 허용 상태에 `working`을 추가한다. `parked`(대기 중)는 그대로 409 `session is parked`.
- **resume(이어서)**: `detached`·`idle`에 `working`을 추가해 같은 대화로 이어 붙일 수 있다.
- **확인 대화상자**: `working` 상태면 "작업 중으로 보입니다. 창을 닫았거나 응답이 없을 때만 진행하세요. 진행하면 이전 창은 더 이상 자동으로 지시받지 않습니다."로 확인한다. `idle`·`unbound`는 기존 문구.

## 결과

- 살아 있는 세션을 다시 띄우면 이전 창은 배정에서 풀린다(새 키가 배정됨) — 이전 창이 계속 Stop을 보내도 allow로 즉시 풀린다.
- 실수로 누르면 두 창이 같은 역할을 맡게 되므로, 확인 대화상자로 오작동을 막는다.

## 검토한 대안

- **PID 생존 감지**: wt.exe 창·claude 프로세스의 실제 생존을 추적해 working을 정확히 판정한다 — 복잡도 대비 이득이 적어 D1로 보류.
