# 0011. 끊긴 세션에 보낼 지시는 새 세션을 띄우지 않고 사용자에게 알린다

- 상태: 확정
- 날짜: 2026-11-14
- 출처: detach-handling plan-v4 (§B)

## 맥락

서버는 파킹 중 연결 끊김만 보고 ESC와 창 닫기를 구분할 수 없다. 실제로는 ESC 개입이 더 흔하다. 기존 규칙(끊김 → 새 세션 실행)은 새 세션이 배정을 가져가 기존 창이 다시 연결되지 못하고 논의 맥락을 잃었다(m1-polish todo-v2-notes N4).

## 결정

지시 전달 규칙(`deliver`)을 peer 상태 기준으로 바꾼다:

| peer 상태 | 지금 | 변경 후 |
|---|---|---|
| 없음(배정 없음) | `launch` | `launch` (그대로) |
| `detached` | `launch` | **`undeliverable`** |
| `parked` | `block` | 그대로 |
| `idle` | `undeliverable` | 그대로 |
| `working` / `unbound` | 없음 | 그대로 |

창을 닫았으면 사용자가 다시 띄우기 버튼으로 새로 띄운다. 배지는 "끊김" 유지, 작업 카드에 다시 띄우기 안내 한 줄.

## 결과

- 사용자가 끊긴 창에 입력하면 다시 연결된다.
- 서버 재시작 뒤에도(세션이 detached로 등록) 새 세션 대신 알림만 뜬다.
- 작업 중(`working`)에 창을 닫으면 감지하지 못한다 — 복구는 작업 종료 후 새 작업 또는 서버 재시작(`unbound` PLANNER는 다시 띄우기).

## 검토한 대안

- **끊김을 "창 닫힘"으로 보고 계속 새 세션 실행**: ESC 개입이 더 흔하고, 새 세션이 배정을 가져가면 기존 창 맥락을 잃는다 → 기각.
- **끊긴 뒤 일정 시간이 지나면 새 세션 실행**: 사용자가 자리를 비운 것과 창을 닫은 것을 여전히 구분 못 함 → 기각.
- **배지를 "사용자 차례"로 표시**: D1에서 사용자가 "끊김 유지"를 선택.
- **`Sessions`가 Orchestrator를 직접 참조해 브로드캐스트**: 의존 방향이 뒤집힘 — 기존 `onNotify`와 같은 콜백 방식을 따름.

## 장기
