# 0020. 프로젝트 제외는 설정에서만 빼고, 진행 중 작업의 프로젝트는 뺄 수 없다

- 상태: 확정
- 날짜: 2026-11-18
- 출처: m3-polish plan-v1 (§3 C)

## 맥락

ADR 0018으로 UI에서 프로젝트를 추가할 수 있게 됐지만, 목록에서 빼는 방법은 설정 파일을 직접 편집하는 것뿐이었다. 사용자 요청(D3): 프로젝트 select가 "프로젝트 선택"이면 `프로젝트 추가`, 특정 프로젝트를 고르면 `프로젝트 제외` 버튼으로 바뀌고, 확인 창을 거쳐 목록(설정 파일 `projects`)에서 뺀다.

## 결정

- **API**: `POST /api/projects/remove` 본문 `{ name }`. 검증: `name` 비어 있으면 400, 없는 이름 404 `unknown project`, **활성 작업의 프로젝트면 409** `project in use`.
- **저장**: `updateConfigFile(configPath, (d) => { delete d.projects[name] })`(임시 파일 `loadConfig` 검증 포함). 실패하면 500 `save failed`(메모리 그대로). 성공하면 메모리 `config.projects[name]` 삭제, 프로젝트 정보 캐시 갱신, `broadcastState()`, 200 `{ ok: true }`.
- **제외는 설정에서만**: 대상 레포의 폴더·파일, `state/`의 세션 기록은 건드리지 않는다.
- **버튼 전환**(D3): select 값이 "프로젝트 선택"이면 `프로젝트 추가`, 특정 프로젝트면 `프로젝트 제외`. 제외 버튼은 활성 작업이 있으면 비활성(진행 중 작업의 프로젝트는 뺄 수 없음). 누르면 확인 창(`'이름' 프로젝트를 목록에서 제외할까요? 설정 파일에서만 빠지고 폴더와 파일은 그대로 남습니다.`)을 거쳐 API를 호출한다.

## 결과

- 제외한 프로젝트로 시작했던 과거 세션 기록(`state.json` sessions)은 남는다 — 화면·판정에 영향 없음(활성 작업만 사용).
- 마지막 프로젝트를 제외하면 `projects`가 빈 객체 — 엄격 검증 통과, 새 작업 버튼은 프로젝트가 없어 비활성.
- 제외 직후 같은 이름으로 다시 추가할 수 있다.

## 검토한 대안

- **제외 시 폴더 삭제**: 위험하고 요구되지 않음 → 설정에서만.
- **추가·제외 버튼을 따로 두기**: 사용자 요청대로 select 값에 따라 한 버튼이 바뀜(D3).
